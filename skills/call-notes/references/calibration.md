# 从最终交付稿校准

## 当前依据与范围

版本：v0.1。依据只有一个真实案例 M-001（2026-09-21 接收），由用户提供的历史助手会话和最终交付稿组成；用户明确说明自己尚不熟悉该专业领域，目标是给老板、至少给自己形成有价值的纪要。

这是“用户对助手内容的选择与改编”，不是用户完全独立写作，也不是准确性金标准。仅提炼方法，不在本文件保留真实机构、交易条款、数字或摘录。原始材料和详细对照仅存本地，生成纪要不依赖该本地材料。

| 依据 | 当前规则 | 适用范围与状态 |
| --- | --- | --- |
| 用户先通过多轮追问理解专业概念，再形成短交付稿 | 理解工作可以充分，交付正文需要再次筛选和压缩；必要科普另放 | 适用于陌生领域纪要；单例观察，待后续案例校准 |
| 交付稿保留可对照条件、关键机制、推进状态及少量相关市场信息 | 围绕业务问题组织；表格承载多项同类条件，短段承载关系与进展 | 当前是交易型会议；不固定成所有会议的四个标题 |
| 交付稿未保留助手大部分延伸判断、背景和通用核查问题 | 控制正文范围；待确认只保留实质歧义，不自动变成完整研究或尽调报告 | 删除只能支持本次取舍，不能证明用户永远不需要这些内容 |
| 用户曾主动追问某段是否来自录音；旧助手随后区分了原话与推断 | 关键立场可回查；会议事实、解释和推断分开 | 用户明确表现出的证据需求；继续观察其呈现偏好 |

初版中转写复核、来源记录、文件检查等属于工作可靠性设计，不宣称为用户个人偏好。不继承其他 skill 的固定语气、加粗规则或汇报结构。

## 新案例到来时

1. 先标明收到什么：原录音/转写、助手初稿、用户交付稿、用户明确解释。缺失部分就注明，不倒推出不存在的原始请求。
2. 比较保留、删除、压缩、改序、改写和新增；区分内容选择、表达偏好、事实纠错与本次特有背景。记录一条变化解决了什么问题，而非只数文字差异。
3. 用户明确说明可作为规则；多次重复的选择可逐步增强。单次观察保留范围和“待校准”状态，不因删了一段就建立永久禁令。新样本与旧样本冲突时先判断场景差异。
4. 修改最少的必要指令；能用一条已有原则覆盖的，不再增加清单、阶段或模板。通用方法与真实材料分开，仓库同步不默认包含录音、转写、终稿或真实摘录。
5. 用未见过的输入检查是否能正确取舍、保留条件、处理证据与不确定性。已经用于提炼的案例只能算回看，合成案例只能测试行为，不能证明用户满意。用户下一次真实交付与改稿是下一轮校准依据。

更新后简要说明学到什么、改了什么、哪些仍不确定。用户要求同步仓库时同步本次通用规则，不把这次授权解释为以后每次都自动推送。
