# 从最终交付稿校准

## 当前依据与范围

版本：v0.2。依据为两个真实案例 M-001、M-002（均于 2026-09-21 接收），各由历史助手内容与用户最终交付稿组成。M-001 是交易推进型纪要；M-002 包含会前准备、完整会议梳理及后续聚焦信息的专题稿。后者关联的分支会话共享部分历史，不重复计为独立案例。用户希望在尚不熟悉专业领域时，为老板、至少为自己形成有价值的纪要。

这是“用户对助手内容的选择与改编”，不是用户完全独立写作，也不是准确性金标准。仅提炼方法，不在本文件保留真实机构、交易条款、数字或摘录。原始材料和详细对照仅存本地，生成纪要不依赖该本地材料。

| 依据 | 当前规则 | 适用范围与状态 |
| --- | --- | --- |
| M-001、M-002 均有多轮概念问答，最终稿未照搬入门教学 | 理解工作可以充分；按交付目的重新选材，必要科普另放 | 两例共同支持；不是禁止正文中的必要短解释 |
| M-001 保留可对照条件、关键机制、推进状态及少量相关市场信息 | 围绕业务问题组织；表格承载多项同类条件，短段承载关系与进展 | 交易型会议的单例结构，不固定成所有会议的四个标题 |
| M-002 用户后续明确聚焦对方掌握的信息，终稿主要沿用专题回答而非完整会议底稿 | 最新的明确重点决定交付范围；时间线、问答和知识准备可用于理解，不必全部写进专题成稿 | 当前专题场景；用户要求全会、时间线或问答时仍应交付 |
| M-002 保留核心判断、分期趋势、支撑逻辑、逐项明细、客户行为和条件分支 | 对方提供的新增信息与判断依据应充分保留；压缩范围，不压掉重要细节 | 信息交流型会议的单例观察；纠正 v0.1 偏向一律短纪要的倾向 |
| 两例均未保留助手的部分延伸建议；M-002 未保留专题回答末尾的执行建议段 | 总结以会议内容为中心，不自动扩成行动策略、尽调清单或长报告 | 两例共同支持控制范围；不代表用户永远不需要建议 |
| M-001 追问某段是否来自录音；M-002 成稿仍反复保留发言来源、预测语气、意向属性和一项尚未得到回答的问题 | 关键结论可回查；区分事实、解释、推断及答复缺口 | 来源意识有重复支持；具体时间戳呈现偏好尚未确定 |
| M-002 删去多处通用核验提醒和误转写说明，但未提供逐项核实证据 | 提醒可以精简；重要疑点不能因终稿删去提醒而自动视作已解决 | 单例编辑行为，不学习为“隐藏不确定性” |

转写复核、来源记录、文件检查等属于工作可靠性设计，不宣称为用户个人偏好。不继承其他 skill 的固定语气、加粗规则或汇报结构。两例都主要是选择和改编助手内容，不据此声称已独立验证个人文风；两例已用于校准，不再算未见测试。

## 新案例到来时

1. 先标明收到什么：原录音/转写、助手初稿、用户交付稿、用户明确解释。缺失部分就注明，不倒推出不存在的原始请求。PDF 等排版终稿需结合逐页视觉检查，尤其留意纯文本提取遗漏的图片表格；缺行或截断不能当作用户删去了该内容。
2. 比较保留、删除、压缩、改序、改写和新增；区分内容选择、表达偏好、事实纠错与本次特有背景。记录一条变化解决了什么问题，而非只数文字差异。
3. 用户明确说明可作为规则；多次重复的选择可逐步增强。单次观察保留范围和“待校准”状态，不因删了一段就建立永久禁令。新样本与旧样本冲突时先判断场景差异。
4. 修改最少的必要指令；能用一条已有原则覆盖的，不再增加清单、阶段或模板。通用方法与真实材料分开，仓库同步不默认包含录音、转写、终稿或真实摘录。
5. 用未见过的输入检查是否能正确取舍、保留条件、处理证据与不确定性。已经用于提炼的案例只能算回看，合成案例只能测试行为，不能证明用户满意。用户下一次真实交付与改稿是下一轮校准依据。

更新后简要说明学到什么、改了什么、哪些仍不确定。用户要求同步仓库时同步本次通用规则，不把这次授权解释为以后每次都自动推送。
