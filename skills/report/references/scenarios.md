# 场景判断：通用兜底，不是个人偏好

本文件只在个人证据不足时帮助组织信息。以下是可选内容，不能变成每次必须出现的标题或段落。

## 先看目的和关系

- 老板可能需要作决策、知道风险或了解价值，也可能只需要一个简短事实。依据本次目的判断，不能自动写成正式周报。
- 同事可能需要交接条件、依赖、责任边界或某项协助，也可能只是知会。不要自动降低准确性、增加口头玩笑或把请求写成命令。
- 混合受众时先覆盖共同需要，必要时区分各人的动作；不凭职级推测情绪或内部政治。

## 按类型选择内容

| 类型 | 可能需要回答的问题 | 容易犯的错误 |
| --- | --- | --- |
| 日报 | 今日发生了什么变化？哪些已完成？哪些受阻？下一个已知动作是什么？ | 把活动清单写成成果，或无依据承诺明日完成 |
| 阶段进度 | 相对目标或上次汇报推进到哪里？偏差和依赖是什么？是否需要决策？ | 把局部完成写成整体完成，遗漏会改变判断的阻碍 |
| 成果展示 | 产出是什么？证据、影响和个人贡献是什么？适用口径和限制是什么？ | 编造指标、混淆测试和真实业务结果、独占团队贡献 |
| FYI | 新信息是什么？影响谁？何时生效？只是知会还是有人需要行动？ | 给纯知会硬加请求，或把必要动作藏在 FYI 下面 |

## 情境变化

- 有风险或延期：忠实表达已知状态、影响和下一步；原因尚未确认时，不归责、不虚构解释。
- 请求决策：背景足够理解选项即可。用户未给出的选项可作为“建议”呈现，不能写成已商定方案。
- 请求协助：具体到对方能做的动作。负责人、期限或资源未确定时，不代其承诺。
- 成果不明显：可以说明验证、排除问题或阶段产出，前提是背景支持；不靠扩大措辞弥补结果不足。
- 无需行动：简洁知会即可；只有已确认无需行动时，才能明确写“无需处理”。

## 形式

从用户要求及样本判断私聊、群消息、邮件、文档或口头稿的篇幅与组织。邮件礼貌套语、汇报标题、固定三段式和结论先行都不是默认个人规则。
